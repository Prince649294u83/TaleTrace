## 1. Executive Forensic Findings

1. **Hardware Mode Integrity Violation**:
   - The CLI was invoked with `--buttons hardware`, but because `http://192.168.1.26:8080/buttons` did not answer at startup, `live_session.py` silently substituted the virtual rehearsal driver instead of failing fast.
   - **Classification**: `INVALID FOR HARDWARE ACCEPTANCE`.
2. **Virtual Driver Flooding & Lost Frames**:
   - The virtual rehearsal driver automatically triggered 11 Meaning Mode toggle cycles.
   - Each toggle invoked `_run_gesture()` $\to$ `self.camera.frame()`, issuing 39 camera capture requests in rapid bursts while previous TCP sockets were still in `TIME_WAIT` or transferring JPEG bytes.
   - This accounts for the accumulation of 39 lost frames.
3. **Session Duration Deadline Defect**:
   - The user requested `--seconds 15`, but because `DeviceLoop` measures duration by tick counts rather than a monotonic wall-clock deadline, the blocking Meaning Mode cycles caused the session to run for **96.98 seconds**.
4. **Supervisor State Flapping**:
   - The supervisor reported `CAMERA_OFF device stopped answering` on single failed captures and immediately flipped back to `CAMERA_ON`, flapping 11 times across the session.
